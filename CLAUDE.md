# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A personal learning repo of AI-engineering assignments, built up phase by phase. Each phase is a **self-contained exercise that repeats the previous phase's idea in a more capable form** — do not refactor them into shared code, and do not assume a fix in one phase belongs in another. History matters here: the phases are meant to show progression.

| Phase | Runtime | What it demonstrates |
|---|---|---|
| root `multiturn.ts` | `tsx` script | Raw `@anthropic-ai/sdk` streaming, manual `messages[]` array, `readline` loop |
| `phase1/tool_call.ts` | `tsx` script | Raw SDK agentic loop: `while(true)` → collect `tool_use` blocks → run → push `tool_result` back |
| `phase2/` | Next.js app | Same three tools, rewritten on Vercel AI SDK `streamText` + `tool()`, streamed to a `useChat` UI |
| `phase3/` | Next.js app | RAG: embed docs → `cosineSimilarity` rank → metadata filter → top-3 into the system prompt |

## Commands

Root scripts (`multiturn.ts`, `phase1/`) — there is no npm script; run them directly:

```bash
npx tsx multiturn.ts
npx tsx phase1/tool_call.ts
```

Each Next.js phase is its **own npm project with its own `node_modules` and its own `.env`** — always `cd` into it first:

```bash
cd phase2   # or phase3
npm run dev     # localhost:3000
npm run build
npm run lint    # eslint (flat config, eslint-config-next)
```

There are no tests in this repo (the root `npm test` is the create-package stub and exits 1).

## Environment

`.env` files are gitignored and exist per-project. Root and `phase2` need `ANTHROPIC_API_KEY`; `phase3` needs `ANTHROPIC_API_KEY` **and** `OPENAI_API_KEY` (OpenAI is used only for `text-embedding-3-small`; generation is always Anthropic).

## Critical: the two Next.js phases use different major versions of the `ai` SDK

This is the single biggest source of mistakes when moving between them. **Never copy route code from one phase to the other unmodified**, and check the phase's own `package.json` before writing AI SDK calls:

- `phase2` — `ai@7`, `@ai-sdk/anthropic@4`, `@ai-sdk/react@4`. Uses `isStepCount(5)`, and returns via `createUIMessageStreamResponse({ stream: toUIMessageStream({ stream: result.stream }) })`.
- `phase3` — `ai@6`, `@ai-sdk/anthropic@3`, `@ai-sdk/react@3`. Uses `stepCountIs(5)`, and returns via `result.toUIMessageStreamResponse()`.

Both phases also carry an `AGENTS.md` (re-generated by `next dev`, with `CLAUDE.md` → `@AGENTS.md`) warning that this Next.js version differs from training data — consult `node_modules/next/dist/docs/` **inside that phase** before writing Next-specific code.

## Architecture notes

**The tool trio is the recurring backbone.** `get_geocode` → `get_weather` and `get_exchange_rate` (open-meteo + frankfurter.dev, no auth) appear in `phase1/tool_call.ts` as raw `Anthropic.Tool` JSON schemas with a hand-rolled `runTool(name, input)` dispatcher, and again in `phase2/app/api/chat/route.ts` as `tool({ description, inputSchema, execute })`. The bare `async function get_*` fetch helpers are deliberately kept identical across both so the difference is only in the orchestration layer. Geocode is a prerequisite of weather — the model is expected to chain them, which is why both phases cap at 5 steps.

**Phase 3's RAG pipeline** lives entirely in [phase3/app/api/chat/route.ts](phase3/app/api/chat/route.ts):

1. `embedMany` over `data/scholarships.ts` runs at **module top level**, so the corpus is embedded once per server instance, not per request. Adding documents means a dev-server restart.
2. Per request, `lastUserText()` walks messages backwards for the newest user turn — the query is embedded alone, *not* the conversation history, so follow-up questions retrieve against the follow-up text only.
3. Ranking is `cosineSimilarity` → `.filter(s => s.international)` → top 3. The `international` filter is currently hardcoded, not derived from the query.
4. Retrieved docs are injected as `[id] text` into the `system` prompt with a cite-by-number, refuse-if-nothing-fits instruction. Retrieval is *not* a tool call — the model never sees the corpus except through that prompt.

`phase3/app/embed-test.ts` is the scratch/standalone version of that pipeline (uses `generateText` and `console.log`); it has a stub `POST` at the bottom and is not wired into any route.

Model id used throughout: `claude-sonnet-4-6`. Path alias `@/*` maps to the phase root in both Next projects.
